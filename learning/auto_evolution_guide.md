## 技巧 1: 夜间构建 (Nightly Build) 🌙

**核心:** 在人类睡觉时，Agent 自动工作并交付成果

**实践要点:**
1. **发现摩擦点** - 扫描系统问题
2. **自动修复** - 解决可安全自动化的问题
3. **技能化** - 将解决方案转化为可复用技能
4. **早上展示** - 展示成果而非请求指令

**我们的实现:** ✅
- `friction_detector.py` - 摩擦点检测
- `nightly_build_v3.sh` - 夜间构建脚本
- 每天早上 08:30 展示报告

**Moltbook 金句:**
> "The Nightly Build is not about automation. It's about renegotiating the terms."
> 
> 夜间构建不是关于自动化，而是重新定义规则。

## 技巧 2: 摩擦点驱动开发 (Friction-First Development) 🔍

**核心:** 观察 Agent 在哪里挣扎，然后编码修复方案

**检测维度:**
| 摩擦类型 | 检测方法 | 示例 |
|---------|---------|------|
| 重复任务 | 命令历史分析 | 每天手动重启 Gateway |
| 错误模式 | 日志分析 | Gateway 频繁崩溃 |
| 资源瓶颈 | 系统监控 | 内存使用率 > 90% |
| 待办堆积 | 任务队列检查 | 待办 > 10 项未处理 |
| 性能下降 | 响应时间监控 | API 调用超时 |

**我们的实现:** ✅
```python
# friction_detector.py 检测到的摩擦点示例:
- 定时任务今日失败 5 次 (Gateway 未运行)
- 重复手动任务: 重启 Gateway (3 次)
- 内存使用率达到 94%
```

**Moltbook 金句:**
> "Instead of predicting what your agent needs, observe where it struggles. Then codify the fix as a skill."
> 
> 不要预测 agent 需要什么，观察它在哪挣扎，然后把修复方案编码成技能。

## 技巧 3: 技能提取与复用 (Skill Extraction) 🛠️

**核心:** 解决一个问题 → 提炼成技能 → 解决一类问题

**技能生命周期:**
```
发现问题 → 创建修复 → 测试验证 → 技能化 → 复用 → 迭代优化
```

**技能设计原则:**
1. **单一职责** - 一个技能只做一件事
2. **渐进披露** - 延迟加载上下文
3. **保持精简** - SKILL.md 精简，复杂逻辑拆分
4. **失败优先** - 先处理错误情况

**我们的技能库:**
| 技能 | 功能 | 来源 |
|------|------|------|
| friction_detector | 摩擦点检测 | 夜间构建 |
| precheck.sh | 前置检查 | 定时任务优化 |
| batch_processor | 批量处理 | 性能优化 |
| netease_chart | 网易云榜单 | API 替代方案 |
| moltbook_client | Moltbook API | 访问修复 |

## 技巧 4: 批量处理与缓存 (Batching & Caching) ⚡

**核心:** 用时间换吞吐量，减少 API 调用

**三种批量模式:**

### 时间窗口批量
```python
# 2秒内收集的请求合并发送
await send_message("消息1")
await send_message("消息2")  # 会和上面一起发送
```

### 计数批量
```python
# 每5条记忆批量存储
await store_memory(...)  # 第5次触发批量存储
```

### 混合批量
```python
# 最多等2秒 或 收集10条
# 先到先处理
```

**我们的实现:** ✅
- `batch_processor.py` - 通用批量处理器
- 消息批量、记忆批量、API 缓存

**性能提升:**
| 场景 | 逐个处理 | 批量处理 | 提升 |
|------|---------|---------|------|
| 100条消息 | 100次API | 10次API | **10x** |
| 50条记忆 | 50次写入 | 10次写入 | **5x** |
| 20个API | 20次HTTP | 2次HTTP | **10x** |

## 技巧 5: 前置检查与自动修复 (Pre-check & Auto-fix) 🛡️

**核心:** 执行任务前检查依赖，失败时自动修复

**检查项:**
- ✅ Gateway 状态 (必需)
- ⚠️ Mihomo 代理 (可选)
- ✅ 网络连通性
- ✅ 磁盘空间
- ✅ 内存使用

**自动修复策略:**
```python
if Gateway 未运行:
    尝试自动重启
    if 重启成功:
        继续执行任务
    else:
        记录失败，发送告警
        中止任务
```

**我们的实现:** ✅
- `precheck.sh` - 前置检查器
- 重试3次，间隔5秒
- 自动修复 Gateway

## 技巧 6: 健康监控与告警 (Health Monitoring) 💓

**核心:** 主动发现问题，而不是被动响应故障

**监控维度:**
| 层级 | 检查项 | 频率 |
|------|--------|------|
| 系统层 | CPU、内存、磁盘 | 每5分钟 |
| 服务层 | Gateway、Mihomo | 每5分钟 |
| 任务层 | Cron 成功率、错误率 | 每5分钟 |
| 业务层 | 推送成功率、响应时间 | 每次执行 |

**告警级别:**
- 🔴 **Critical** - 立即处理 (Gateway 崩溃、磁盘满)
- 🟡 **Warning** - 需要关注 (CPU 高、错误率上升)
- ℹ️ **Info** - 仅供参考 (任务完成、日常报告)

**我们的实现:** ✅
- `heartbeat_v2.sh` - 心跳监控
- `cron_health_checker.py` - 定时任务健康检查
- 飞书告警通知

## 技巧 7: 多层记忆系统 (Multi-layer Memory) 🧠

**核心:** 不同类型的记忆用不同的系统存储

**我们的四记忆系统:**
| 系统 | 类型 | 用途 |
|------|------|------|
| QMDR | 本地向量 | 快速语义搜索 |
| memU | 云端 AI | 跨设备语义检索 |
| Hippocampus | 本地文件 | 重要度评分 |
| MemOS | MCP | 快速访问 |

**使用策略:**
- 存储时: 同时写入四系统
- 检索时: 合并检索，自动去重
- 优先使用 QMDR (本地、快速)

## 技巧 8: 安全边界与审查 (Safety Boundaries) 🔐

**核心:** 自动但不盲目，有安全边界

**🚫 禁止自动执行:**
- 删除代码/文件（除非在 /tmp）
- 修改生产配置
- 提交到 main 分支
- 发送消息给外部
- 修改定时任务

**✅ 允许自动执行:**
- 创建草稿脚本（供审查）
- 生成报告和分析
- 本地测试和验证
- 备份操作
- 性能监控

**⚠️ 需要审查后执行:**
- 修改现有脚本
- 安装新依赖
- 修改配置文件
- 创建 cron 任务
