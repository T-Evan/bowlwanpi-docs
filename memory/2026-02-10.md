## 🔍 渐进式披露能力对比

### 原生 Rules（工具特定）

**特点：**
- 📁 **目录感知** - 不同子目录可以有不同规则
- 🎯 **文件类型匹配** - 如 `*.ts` 规则只对 TypeScript 生效
- ⚡ **实时切换** - 编辑不同文件时自动应用对应规则

**例子（Cursor）：**
```markdown
.cursor/rules/
├── frontend.md      # 前端代码规则
├── backend.md       # 后端代码规则  
├── api.md           # API 层规则
└── tests.md         # 测试规则
```
→ 打开 `src/api/user.ts` 时，自动组合 `backend.md + api.md`

---

### AGENTS.md

**特点：**
- 🌳 **层级继承** - 子目录 AGENTS.md 覆盖父目录
- 📄 **文档化** - 更像给 AI 的"使用说明"
- 🔗 **可链接** - 可以链接到具体 rule 文件

**渐进式披露：**
```
项目/
├── AGENTS.md        # 项目级基础规则
├── frontend/
│   └── AGENTS.md    # 覆盖：前端特有规则
└── backend/
    └── AGENTS.md    # 覆盖：后端特有规则
```

---

## ⚡ 关键区别

| 维度 | 原生 Rules | AGENTS.md |
|------|-----------|-----------|
| **粒度** | 文件类型/目录 | 目录层级 |
| **动态性** | 高（实时匹配） | 中（层级覆盖） |
| **工具绑定** | 强 | 弱（通用格式） |
| **可组合性** | 工具决定 | 手动链接 |

---

## 💡 最佳实践

**结合使用：**
```
AGENTS.md → "项目整体上下文 + 链接到具体 rules"
.cursor/rules/*.md → "渐进式、细粒度的编码规则"
```
